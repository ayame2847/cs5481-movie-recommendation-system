# 小组协作约定

## 开始一项工作

先在 Issue 或小组记录中写清要解决的问题、负责人和预期产物。算法和环境等共同决策先讨论确定，再更新 README。成员名单和分工确定后补在项目文档中，不先写虚构信息。

## 代码和文件放哪里

- 可复用的处理、训练、推荐和评估逻辑放 `src/`。
- 探索过程放 `notebooks/`。整理好可复用逻辑后再移进 `src/`。
- 实验配置放 `configs/`，不要把本机绝对路径写死在代码里。
- 数据放 `data/`，不要上传原始数据、处理后的数据、模型权重和缓存。
- 经确认的结果表和图放 `results/`，报告和演示材料放 `reports/`。

## 提交改动

建议每项工作使用一个含义清楚的分支，例如 `docs/data-guide`、`feature/data-loading` 或 `fix/seen-movies-filter`。一次提交集中处理一件事，提交说明直接写改了什么。

合并前说明改动内容和验证方法；多人合作时尽量由另一位成员看一遍。提交前检查差异，别把密钥、本地路径、数据集或临时实验产物一起带上。

## 实验怎么记

每次正式实验复制 [实验记录模板](实验记录模板.md)，填上真实配置和输出位置。调整参数后保留新记录，不用新结果覆盖旧结果却不留说明。

比较算法时统一数据划分、相关性定义、候选集合和评价口径。参数通过验证集确定，最终测试结果不能用来反复挑参数。

## 完成一项功能后

- 确认命令能在文档指定的工作目录下运行。
- 检查推荐是否过滤已观察的评分历史，片名和类型是否对应正确。
- 更新受影响的运行说明和配置说明。
- 在记录中说明还没完成或无法复现的部分。
